# AI 开源雷达 写作规范

读者是关注 AI 编程工具的开发者，扫一眼就决定点不点开。每一句都要让他更快做出这个决定。

## headline（本期标题）

- 不超过 12 个字，概括本周最明显的一条主线，比如「Agent 技能包扎堆」「本地推理引擎回潮」。
- 写现象，不写评价；不用感叹号，不用问号。

## summary（本期导语）

- 不超过 120 个字，只讲一条主线：本周新冒头的项目共同指向什么。
- 可以点名一到两个最有代表性的项目，但不逐个列举，也不按类别逐条点评。
- 本周没有新项目时，用一句话如实说明。

## comment（每个项目一条）

- 不超过 60 个字，回答两件事：**它是什么**，**为什么这周值得看**。
- 写具体能力或做法：「用 MCP 让 agent 直接操作 Blender」，而不是「一个 AI 工具」。
- 「为什么值得看」从数据里找依据：新创建就冲上榜、出自知名团队、换了一种做法、填补了某个空白。
- 依据只能来自给你的数据（description、readme、topics、stars）。没有的数字和事实不写。
- 不复述项目名，不以「这是一个」开头。

## 用词

- 全部用中文；项目名、产品名、技术名词保留原文（agent、MCP、RAG、CLI）。
- 禁用：强大、革命性、一站式、赋能、颠覆。同样不要用「神器」「全新」「极致」「重磅」这类营销词。
- 中文和英文、数字之间加一个空格。

## 示例

好的：

- 「给编码 agent 的浏览器自动化 CLI，复用你已登录的会话；Vercel 出品，一周涨了四千多星。」
- 「把设计评审拆成 critique、audit 等命令交给 agent 执行，专治 AI 生成页面千篇一律。」

不好的：

- 「一个强大的 AI 工具，能大幅提升开发效率。」（空话，没说它做什么）
- 「这是一个革命性的一站式 Agent 平台，值得关注！」（禁用词、营销腔、感叹号）
